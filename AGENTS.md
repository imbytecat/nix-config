# AGENTS.md

## Repo Shape

- Nix flake for `awesome-macbook-air` (`aarch64-darwin`), `awesome-pc` (`x86_64-linux`), `homelab-server` (`x86_64-linux`, root-only Docker VM), `mihomo-gateway` (`x86_64-linux`, root-only gateway), `ovh-ks-5` (`x86_64-linux`, root-only Docker server), and `agent-server` (`x86_64-linux`, headless daily machine). Uses Lix.
- Flake attr, host directory, and `networking.hostName` must match exactly; `just _guard` calls `_valid` first, then compares `hostname -s` with the host argument.
- Dendritic layout on flake-parts: `flake.nix` only declares inputs and auto-imports every `modules/**/*.nix` as a flake-parts module; paths containing `/_` are plain data or helpers imported by path. One feature per file: a feature contributes plain NixOS / nix-darwin / Home Manager modules to role aspects `aspects.<class>.<role>` (option in `modules/flake/aspects.nix`). A feature that spans platforms stays in one file and keeps its platform differences in the class key, not in conditionals. Aspects are deliberately not `flake.modules`: Lix warns `unknown flake output 'modules'`.
- Roles: `base` is shared per platform. `daily` gives Mac, PC and `agent-server` the `imbytecat` account and shared Home Manager environment. Mac and PC add `desktop` for GUI packages and integration. `server` is the root-only baseline for service hosts and the gateway. `modules/hosts.nix` composes these roles, NixOS adapters such as `root-ssh` and a bootloader, and `hosts/<host>/` for hardware, disks and machine overrides. Every host gets a generated `checks.x86_64-linux.eval-<host>`.
- Inner modules get `inputs` and `sshKeys` through `specialArgs`, plus `username` on daily hosts only; root-only servers receive no `username` because nothing in their closure needs one. Home Manager gets `inputs` through `extraSpecialArgs`, plus `username` on daily hosts. There is no `system` arg: use `pkgs.stdenv.hostPlatform.system` in config values. Flake-level code (hosts, packages, checks) uses the top-level flake-parts `inputs`/`config`.
- The server baseline excludes Home Manager, catppuccin, zsh, 1Password, Docker, unfree and desktop features. `mihomo-gateway` adds the `gateway` aspect. `homelab-server` and `ovh-ks-5` enable Docker and Tailscale.

## Commands

- Local activation: `just switch <host>`; hostname mismatch is refused. NixOS-only: `just boot <host>`, `just rollback`.
- Build without activating: `just build <host>`. Compare current generation: `just diff <host>` (auto-builds first). Hunt cache misses: `just dry <host>`.
- Checks: `just fmt`, `just eval`, `just check`. `just eval` only covers current-platform hosts, but eval-only cross-checks work from Linux too: `nix eval .#darwinConfigurations.<host>.system.drvPath` (building/activating Darwin still needs a Mac). Run evals sequentially — parallel `nix eval` can die on a busy eval-cache SQLite.
- Flake evals only see git-tracked files. `git add` new `.nix` files before any `nix eval`/`just build`, or you get "No such file or directory" against the store copy of the repo.
- `nix fmt` formats the whole repo via treefmt (config in `treefmt.nix`, currently nixfmt only); `just fmt` is just an alias. Do not go back to hand-assembling a file list.
- `nix flake check` (= `just check`) evaluates every host **and** runs `checks.formatting` (treefmt) + `checks.lint` (statix + deadnix). Both are expected to be clean — a warning is a regression, not background noise. `just lint` runs the linters alone.
- NixOS install/update: 首装优先从另一台机器运行 `just install <host> <remote>`（nixos-anywhere, `--build-on remote`）；Live 本机备用路径直接运行本仓 `packages.x86_64-linux.disko-install`，显式传 `--flake`、`--disk` 和 `--write-efi-boot-entries`；之后用 `just deploy <host> <remote>` / `just deploy-boot <host> <remote>`。
- `disko-install` **忽略** flake 里的 `device`，强制 CLI `--disk <name> <path>`（见上游 install-cli.nix）。`awesome-pc` 默认 by-id 在 `hosts/awesome-pc/disko.nix`；Live 对不上时只替换 CLI 设备路径。本地安装使用已提交的 hardware config。`just install` only asks nixos-anywhere to generate hardware config when `hosts/<host>/hardware-configuration.nix` is git-tracked (untracked files never reach the target build); generation overwrites that file in the caller worktree before the target build.
- `just install` deliberately passes **no** substituters/keys/experimental-features: nixos-anywhere defaults to `machineSubstituters=y`, which evals the target's `nix.settings.{substituters,trusted-public-keys}` and appends them to the installer's `~/.config/nix/nix.conf`, and it already puts `--extra-experimental-features 'nix-command flakes'` on every nix invocation (`src/nixos-anywhere.sh`). Do not re-add a hand-written cache list there — it silently drifts from `nix.settings`. Only `--no-substitute-on-destination` / `--no-use-machine-substituters` turn that off; `--option` does not.
- `.vscode/settings.json` is committed and static: nixd `options` mounts nixos + nix-darwin + home-manager option sets side by side (representative hosts `awesome-pc` / `awesome-macbook-air`; option *declarations* come from imported modules, so same-class hosts share them). No generation step.
- `nix develop` provides repo tools (`just`, `nixd`, `nixfmt`, `statix`, `deadnix`, `nvd`, `nix-tree`, treefmt wrapper) without relying on the host HM profile. Its `nixfmt` is `treefmt.config.programs.nixfmt.package` on purpose: `.vscode/settings.json` makes nixd format with bare `nixfmt`, so format-on-save must resolve to the exact binary `nix fmt` and `checks.formatting` use. Without it, Mac would fall back to the HM copy from `nixpkgs-unstable`, which can drift from the repo's `nixpkgs`.
- `homelab-server` is a Proxmox VE QEMU VM with systemd-boot, DHCP, VirtIO initrd support, QEMU guest agent, root-only access, and Docker. Its disko target defaults to `/dev/sda`; change the host-local default before a destructive install if PVE presents another device.
- `ovh-ks-5` is OVH bare metal: `/dev/nvme{0,1}n1`, RAID1 ESP at `/boot/efi` (vfat, 512 MiB, md metadata 1.0), RAID1 `/boot` (ext4, 2 GiB, metadata 1.2), and RAID1 ext4 root (metadata 1.2). It uses GRUB hybrid/removable boot, DHCP, root-only access, and Docker with its built-in Compose plugin. Its tracked `hardware-configuration.nix` is the first-install generation target; commit the target scan after `just install`.
- `ovh-ks-5` backups live in `hosts/ovh-ks-5/backup.nix`: one `services.restic.backups.stacks` job snapshots `/opt/stacks` (every stack keeps its bind mounts inside its own directory, dockge-style) plus `/var/lib/docker/volumes`, so a single snapshot is a movable machine. `backupPrepareCommand` probes every running container for `pg_dumpall` and writes `/opt/stacks/.dumps/<container>.sql.zst` into the tree — logical dumps, because a tar of a live PG data dir is only crash-consistent. A failed dump does **not** abort the snapshot: it drops a `FAILED-<name>` marker and `backupCleanupCommand` fails the unit afterwards, so a partial snapshot still lands but never looks green.
- `/etc/restic` contains exactly the hand-written `repository` and `password` files; SFTP needs no environment file. The service never initializes a repository automatically: `restic-stacks init` is an explicit first-creation step, so a wrong repository URL fails closed instead of silently creating an empty history. Keep `/etc/restic/{repository,password}` and `/root/.ssh/id_ed25519` in 1Password; this deliberate exception mirrors `/etc/mihomo/env`, so restic and Mihomo stay outside sops-nix.
- The restic target is a HostBrr Storagebox over SFTP, and **this repo is public**, so no hostname/username/port goes into git. `/etc/restic/repository` holds the full `sftp://user@host:port//abs/path` URL; no `/root/.ssh/config` alias or `known_hosts` priming. `backup.nix` uses `StrictHostKeyChecking=accept-new`; verified with both SSH files deleted that backup succeeds, pins the key, and restores a canary. The oneshot unit has no 90-second start cap. Its daily `--read-data-subset=2%` check is random corruption sampling, not deterministic 50-day coverage.
- `agent-server` is a second OVH KS-5 with `ovh-ks-5`'s disks and GRUB layout except a RAID0 root (ESP and `/boot` stay RAID1 so firmware boots from either disk); it deliberately has no backup, so a dead disk means reinstall and data loss. Its tracked `hardware-configuration.nix` is the first-install target scan (identical to `ovh-ks-5`'s). Only SSH 22 and Tailscale's UDP port are public; services stay on loopback and reach the tailnet through `tailscale serve`. T3 runs as `imbytecat` with linger and binds `127.0.0.1:3773`. Keep pairing and credentials under that account. The `root-ssh` adapter supplies the root public-key entry for deployment. See README for Tailscale Serve and SOPS enrollment.
- `just install` kexecs twice because the kernel that creates md arrays decides which kernels can assemble them: 6.19+ writes a logical-block-size field into the superblock that older kernels refuse, and nixos-images ships its kexec image with the latest kernel (`installer.nix` imports `latest-zfs-kernel.nix`; upstream nixos-anywhere#673 / disko#1276 are still open). So nixos-anywhere first boots `kexec-bootstrap` (the upstream image, only to get Nix on the target; its hash may be updated freely when upstream re-uploads), the recipe builds `packages.x86_64-linux.kexec-installer` (nixos-images modules + this repo's nixpkgs + default LTS kernel) on the target over `ssh-ng`, kexecs into it, aborts if its kernel is newer than the target's, and only then runs disko/install. That image drops upstream `restore-remote-access.nix` and reuses only its initrd service, because the module still sets the removed `boot.initrd.systemd.enable`.

## Where Things Go

- Cross-platform features live in top-level files or topic dirs under `modules/`: `nix.nix` (Lix, caches, registry, weekly GC with `--delete-older-than 30d` — systemd `dates` on NixOS, launchd `interval` on Darwin —, `trusted-users` on daily hosts, store optimise on servers), `users.nix` (the human account and sudo; Darwin puts it in base because nix-darwin's homebrew and user defaults need `system.primaryUser`), `ssh.nix` (sshd everywhere, root keys and hardening on servers, the HM SSH client), `home.nix` (shared HM integration and daily-user composition plus HM base packages), `catppuccin.nix`, `fonts.nix`, `1password.nix`, `tailscale.nix`, `shell/`, `dev/`, `agents/`, `desktop/`.
- Platform-only plumbing lives in `modules/nixos/` (`base`, `daily`, `desktop`, `android-emulator`, `input-method`, `server`, and the `qemu-guest`/`systemd-boot`/`grub-raid` adapters) and `modules/darwin/` (`homebrew`, `defaults`); `modules/gateway/` is the NixOS-only gateway role.
- `aspects.nixos.base` holds only what every NixOS role needs: Nix settings, disko, locale/timezone, sshd, zram, the landing CLI baseline (curl, git, lsof, pciutils, usbutils, smartmontools) and Ghostty terminfo. Role-shaped facts go to `daily`/`server`, adapters stay separate, machine facts go to `hosts/<host>/`. Server echo tools (btop, neovim, ouch) stay in `nixos/server.nix`: hoisting them into base would double-install them on daily hosts where HM owns the configured version. Every NixOS host composes exactly one boot adapter; base is bootloader-agnostic.
- Do not create a Docker wrapper or aspect while its shared implementation is one native line. Daily NixOS enables Docker in `nixos/daily.nix` and grants the `docker` group in `users.nix` (a user privilege); root-only Docker servers enable it in their host modules. The default nixpkgs Docker package already carries the Compose plugin, so do not add `docker-compose`. `services.tailscale.enable` follows the same pattern: `tailscale.nix` for daily hosts (with the Darwin `tailscale-app` cask), host-local for servers that want it, never on `mihomo-gateway`.
- `modules/desktop/apps.nix` is the single GUI app list for both desktops: `both` maps each Homebrew cask to the nixpkgs attr of the same app, and platform-only casks/MAS/packages sit in the same file. Apps with configuration, services or special install needs get their own feature file instead (`1password.nix`, `tailscale.nix`, `shell/ghostty.nix`). XWayland Qt5 apps that need fcitx env (`wechat-fcitx`, `wpsoffice-fcitx`) are wrapped in the overlay. Single-host casks/packages stay in `hosts/<host>/default.nix` (for example `thaw`); GPU drivers are hardware and stay there too.
- `modules/nixos/desktop.nix` owns Plasma 6 (Wayland-only + SDDM), NetworkManager, printing/Avahi, AppImage binfmt, Bluetooth and Logitech peripherals (`programs.solaar` installs Solaar and enables `hardware.logitech.wireless`; piper/ratbagd are intentionally not installed), plus the user's Plasma/Konsole HM config through `home-manager.users.${username}`. `modules/nixos/input-method.nix` owns fcitx5 + WowType, the keyd CapsLock mapping and the matching HM fcitx5 files. Linux-only HM config is written from these NixOS modules so it can never reach Darwin.
- `modules/shell/ghostty.nix` holds everything Ghostty: the Darwin cask, the desktop HM settings (Linux installs the package through HM because the HM module's systemd/D-Bus integration needs one; Darwin uses `package = null`), and the terminfo in NixOS base.
- `modules/dev/languages.nix` (HM `daily`): shared development runtimes/tooling (`bun`, `go`, `python3`, `uv`, `mise`, `android-tools`, LSPs, linters). An LSP/formatter/linter earns its place only when omp's `lsp` tool, a VS Code extension, or agent shell sessions actually resolve it from PATH; VS Code extensions that bundle their own server do not count (evidence: `docs/research/dev-language-tools-2026-11-15.md`). Neovim (`modules/dev/neovim.nix`) is plain `programs.neovim` on purpose: LazyVim was removed because it was barely used and its extras expected tools that were never installed. `android-tools` is enough for `adb`/`fastboot`; in 2026 nixos-unstable no longer needs `programs.adb`, `adbusers`, or `android-udev-rules` because systemd 258 handles uaccess. Android development runs without Android Studio: Android CLI (`android`) is deliberately not a Nix package — projects that use it pin it in their own mise config; it installs SDK packages into a mutable SDK at `ANDROID_HOME` (each platform's default path) and starts the AVDs that project repos generate as `config.ini`. The SDK stays outside the store (no `androidenv`) because AGP and Flutter auto-download NDK/platform packages into the SDK root; HM still writes `~/.androidrc` with `--no-metrics` because the CLI's telemetry is on by default, whoever installs the binary (evidence: `docs/research/android-cli-2026-11-22.md`, `docs/research/android-emulator-2026-11-22.md`). Flutter is project-pinned through mise too (no `fvm`); `FLUTTER_SUPPRESS_ANALYTICS=true` turns its default-on telemetry off, because Flutter's own switch lives in `~/.dart-tool/dart-flutter-telemetry.config`, a state file the tools rewrite.
- `modules/agents/` 分成两条轴：`_bundles/` 声明跨 agent 的 **behavior bundle**，`codex.nix`、`codex-plugins.nix`、`claude-code.nix`、`omp.nix`、`pi.nix`、`dsh.nix`、`skills.nix` 只负责映射到 Codex plugin、Claude Code plugin/settings、OMP extension/rule、Pi 配置、DSH patch 与共享 skill 目录。`_bundles/default.nix` 是 plain-attr registry，不创建 repo option；Ponytail/Caveman 的 pin-specific packaging、OMP 文件和 skill 取舍只在各自 bundle 改。`_ai-catalog.nix` 是 AI gateway endpoint、provider identity、model IDs/metadata 的唯一来源（plain attrs，由 `agents/default.nix` 通过 `_module.args.aiCatalog` 注入 HM `daily`，SOPS 登录同步也用它）。同一角色提供 Node.js 供插件 hooks 使用。Models 位于 `providers.<family>.<nick>`（family 使用客户端内置厂商标识，如 anthropic、openai、deepseek）；映射文件通过扁平 `models.<nick>` view（含 `provider`）、`ref "<nick>"`（→ `provider/id`）或 `providers.<family>` 投影消费。模型/endpoint 只在 catalog 改，不在映射文件分散修改。新增模型时引用 `models-dev` flake input 的厂商和条目 ID；catalog 合并 provider 与 base model 的元数据，网关 ID、显示名或已实测的能力差异在条目旁覆盖。Pi 和 OMP 的原生模型继承内置元数据；仅当网关 ID 与原生 ID 不同时才生成额外条目。Pi 别名的 `thinkingLevelMap` 与 DSH 的 `reasoningEfforts` 从 catalog 生成；各 agent 自己选默认档位，用 `effortFor` 校验。模型可用性只认网关 `/v1/models`，网关路由是否遵守推理参数只能实测（来源与命令见 `docs/research/ai-model-metadata-2026-11-21.md`）。
- Agent 映射的落法：`codex.nix` 用内置 `openai` 和 `openai_base_url` 指向 Furtherverse。TUI 和 T3 的 app-server 需要原生登录凭据，T3 启动前用 SOPS 网关 key 执行 `codex login --with-api-key`；`codex-plugins.nix` 聚合 bundle plugin、Codex 0.146 cache 兼容层与激活时的 hook 信任；`omp.nix` 生成 `~/.omp/agent/{models,config}.yml` 并合并 bundle 的 extension/files；catalog→gateway provider 投影单一化在 `_gateway-providers.nix`：OMP 使用自己的 Moonshot ID `moonshot`，整体写入 models.yml，Pi 整体写入 `~/.pi/agent/models.json`，DSH 复用路由的 api/baseUrl；`skills.nix` 把 bundle 与 skill-only 输入逐项 link 到 `~/.agents/skills`，父目录保持可写。
- Claude Code 与 Pi：`claude-code.nix` 用 HM `programs.claude-code`（llm-agents 包）；bundle 的 `claude` 键是自带 `.claude-plugin/` 的上游仓库根，HM 把每个 plugin 整目录 link 成 `~/.claude/skills/<name>` personal plugin，hooks/skills/commands 随 manifest 生效。模型只经 settings `env` 的 `ANTHROPIC_DEFAULT_{FABLE,OPUS,SONNET,HAIKU}_MODEL` 指到 catalog（context 1M 的加 `[1m]`：网关不替它确认扩展上下文），`apiKeyHelper` 读 SOPS 的网关变量，不另设 `ANTHROPIC_AUTH_TOKEN`。遥测类开关全开：`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 加冗余的单项开关（原因见 Conventions 的 Telemetry）；`ENABLE_TOOL_SEARCH=false` 因为网关丢 Anthropic server tool（`web_search` 实测，tool search 未实测）。这些放 settings `env` 而非 session 变量，从 T3 服务起的会话也生效。`pi.nix` 和 OMP 用原生 provider ID 接 Furtherverse，路由只覆盖 base URL 和凭据。Pi 的 `enabledModels` 取自网关 catalog。apiKey 写成网关变量的 `$NAME` 插值，`enableInstallTelemetry = false`（不管更新检查），`PI_SKIP_VERSION_CHECK=1` 只在 HM session 变量里。
- DeepSeek Harness：`agents/dsh.nix` 安装 `llm-agents` 的 `dsh`（跨平台，命中 `cache.numtide.com`；nixpkgs 的 `deepseek-harness` 仅 Linux 且版本更旧），并只写 home 级 `~/.dsh/cordis.patch.yml`（叠在每个 profile 之后），用 `llm-pi-ai` 的 `deepseek` 路由（`openai-completions`，api/baseUrl 取自 `_gateway-providers.nix`）挂 catalog 的 `deepseek` 并设为 `agent-default-model`。不用原生 `llm-deepseek`：它默认把整段 `dsh_session_log`（每请求至多 8 MiB）作为额外字段发给 `baseURL`。不声明 `off` 档：当前网关把 DeepSeek 转给 `commandcode`，它不理会任何关思考参数（2026-11-21 实测，见 `docs/research/ai-model-metadata-2026-11-21.md`）。patch 按 id 整行替换 config，UI 在 profile patch 里改的同名行会被它覆盖。
- DSH 隐私与搜索：同一 patch 把 `session-telemetry-otel` 行 `disabled: true`（等同 `DSH_TELEMETRY_DISABLED` 的启动 patch；默认 `FEEDBACK_ONLY` 会在点赞/点踩/`/feedback` 后上传整段 session log 到 `dsh-otel-collector.deepseeksvc.com`）。`desktop` profile 才挂的 product analytics 不处理。DSH 的官方 API key、账号和两个 DeepSeek 搜索后端都禁用。Furtherverse 的 `/v1/tools/search` 和 `/v1/tools/fetch` 均返回 503（2026-11-24 实测），所以关闭 `web_search`，`web_fetch` 使用内置 HTTP 抓取；其 SSRF 校验会拒绝 mihomo fake-ip。
- DSH 权限：同一 patch 的 `permission` 行把新会话默认预设设为 `danger-full-access`（完全文件访问 + `never` 审批，对齐 Codex 的 `never` + `danger-full-access`）。DSH 的 `never` 是自动拒绝而非自动批准，只因完全访问下没有需要升权的操作才等于免授权。该行 config 整行替换，必须照抄上游的 `read-only`/`workspace-write`/`danger-full-access` 三个预设；`/permission` 与 `dsh headless --permission-mode` 仍可逐会话切换。不用上游的 `DSH_PERMISSION_MODE` 环境变量：它只在带 HM 会话变量的 shell 里生效，与 telemetry 选 patch 的理由相同。
- ponytail（`inputs.ponytail`，`flake = false`）是 behavior bundle，不等于某个 host 的 plugin：`omp.nix` 把上游仓库根目录列进 `extensions`，loader 认 `package.json` 的 `pi.extensions`，`before_agent_start` 每轮注入 ruleset 并注册 `/ponytail` 档位与 `/ponytail-*` 命令；`codex-plugins.nix` 经 HM marketplace/cache 加载上游正式 plugin；`claude-code.nix` 直接挂上游的 Claude Code plugin。`materializeCodexPlugins` 在 link 后把 store symlink 落成真实可清理目录（Codex 0.146 只把真实目录算 installed）。Codex 把 hook 的信任同时钉在声明 hash 与整个插件目录的内容 hash 上，插件或 Codex 一更新，手钉的 hash 就失效，hook 静默报 `Failed`（曾因此长期没生效）；Codex 没有持久的“信任全部”开关（`--dangerously-bypass-hook-trust` 只管单次调用，`app-server` 也不认）。所以不钉 hash，由 `trustCodexHooks` 激活步骤经 `codex app-server` 的 `hooks/list` + `config/batchWrite`（与 TUI 审批同一写法）信任 Codex 在 `$HOME` 下列出的全部 hook；Codex 本来就是 `never` 审批 + 完全访问，这一步不扩大权限。项目自带的 `.codex/` hook 不在其列，仍按项目审批。Ponytail skills 由各家 plugin 自带，不再铺共享副本。
- caveman（`inputs.caveman`，ponytail 的另一半）也是 behavior bundle，但上游没有 Pi adapter：`agents/_bundles/caveman.nix` 给 OMP 提供 always-apply rule 与 `/caveman` command，给 Codex 生成封装上游 `.codex/hooks.json` 的最小 lifecycle plugin，给 Claude Code 直接挂上游 `.claude-plugin`；上游命令从 git 根目录找 `codex-sessionstart.js`，只在 caveman 自己的仓库里成立，bundle 把它改指 store 中的脚本，上游改写法时求值报错。共享 skills 同样由该 bundle 导出。`cavecrew` 与 `caveman-stats` 不铺进共享目录（前者依赖 Claude subagent，后者依赖 Claude session hook），Claude Code 经 plugin 自带它们；`caveman-shrink` 保持 opt-in。
- `agents/t3code.nix` 用 HM `programs.t3code`：装包（`t3` CLI）、把 omp 的 Local ACP 合并进 `settings.json`（命令名必须是 `omp`），`server` 起常驻 daemon（launchd agent / systemd user service）；桌面机用 `--lan` 做直连配对，NixOS 桌面只在 `tailscale0` 放行 3773。`agent-server` 经 loopback 和 Tailscale Serve 提供访问。NixOS 日用机都开 linger。模块的服务不经 login shell，所以给它补 PATH、由 SOPS 渲染的 dotenv和 `T3CODE_TELEMETRY_ENABLED=false`（同时放 session 变量给 CLI），macOS 的 `ProcessType` 改回 `Interactive`。桌面端（同一 llm-agents 包的 `desktop` output，Nix 构建不自更新，装在两个 `desktop` role）只当客户端：HM 激活时把 `~/.t3/userdata/desktop-settings.json` 的 `localEnvironmentEnabled` 合并为 `false`，否则它要在同一个 `~/.t3` 起本地服务器，撞上 daemon 的锁就弹 “This T3 home is unavailable” 并退出；直连用 `t3 pair`，把链接贴进桌面端的 Add environment。T3 Connect 用 Nix 的 cloudflared；每台需要中继的机器手动运行 `t3 connect link` 授权，然后重启 HM 的 t3code 服务。agent 只能在 daemon 里跑：桌面端本地环境经 `zsh -ilc` 只导入白名单变量（PATH、LANG、SSH_AUTH_SOCK、`T3CODE_TELEMETRY_ENABLED` 等），不含网关密钥，Codex 会报 `Missing environment variable: FURTHERVERSE_API_KEY`。不用 managed policy：它是 root 写的机器级文件，缺 `schemaVersion`/`organization` 服务器就报 `ManagedPolicyFileError` 拒绝启动（曾因此起不来）。
- mattpocock/skills（`inputs.mattpocock-skills`）是 skill-only distribution，不是 behavior bundle：22 个流程 skill（grilling → to-spec → to-tickets → implement/tdd → code-review）由 `agents/skills.nix` link 到 `~/.agents/skills`。只取 `skills/{engineering,productivity}`（= 上游 `.claude-plugin/plugin.json` 清单），不铺 `deprecated`/`in-progress`/`misc`/`personal`。13 个带 `disable-model-invocation` 的 skill 只能显式调用；实测 Codex/OMP 都只暴露同 9 个 model-invocable skill。用前每仓跑一次 `/skill:setup-matt-pocock-skills` 生成 `docs/agents/{issue-tracker,domain,triage-labels}.md`；升级 `nix flake update mattpocock-skills`。

## Nix / Package Gotchas

- Darwin pkgs are imported in the `darwin` helper of `modules/hosts.nix` from `inputs.nixpkgs-unstable` with `allowUnfree` and overlays; do not add `nixpkgs.config` in Darwin modules.
- NixOS `allowUnfree` and overlays are in `modules/nixos/daily.nix`, so servers (base + server aspects) have neither in their closure; do not move them into base. `nix-ld` lives in `nixos/daily.nix` for prebuilt binaries on every daily host (mise runtimes, Android SDK tools, VS Code/Cursor Remote). `nixos/android-emulator.nix` splits the emulator's libraries by role, and NixOS merges both lists with the module defaults. `daily` gets the headless set, `libx11`: the launcher and its `-headless` qemu link `libX11.so.6` even with `-no-window`. `desktop` gets the windowed set: PulseAudio for the windowed qemu, Qt xcb, NSS for QtWebEngine, and `libglvnd` for `-gpu host`. NixOS desktops get both sets. On Linux `-gpu host` renders through GLX and needs an X display; headless runs fall back to SwiftShader. Nothing in nixpkgs provides `libtiff.so.5` (it ships `.so.6`); only Qt's TIFF image plugin needs it. Verified 2026-11-25 on emulator 37.3.10: 104 Gradle Managed Device tests pass headless, and the windowed emulator boots on Xvfb.
- Repo-local packages 由 `overlays/default.nix` 统一 `callPackage` 后暴露为 `pkgs.<name>`；模块只消费 `pkgs`，`flake.packages` 复用同一 attr。不要从模块写 `callPackage ../../pkgs/...`，否则 package seam 泄漏仓库布局。
- Channels are disabled. `modules/nix.nix` pins registry and the shared `nix.nixPath` to flake `inputs.nixpkgs`; do not add `<nixpkgs>`/channel-based paths. Keep this working cross-platform option until nix-darwin migrates its `NIX_PATH` handling too; the NixOS rename warning is an accepted exception, not a reason to add a platform-specific mapping.
- `llm-agents` packages are consumed directly via `inputs.llm-agents.packages.${pkgs.stdenv.hostPlatform.system}.*` in `modules/agents/`; never add an overlay. `llm-agents` intentionally does not follow this repo's nixpkgs; changing that will miss `cache.numtide.com`.
- WowType (fcitx5 pinyin addon) is consumed directly as `inputs.wowtype.packages.${pkgs.stdenv.hostPlatform.system}.default` from the upstream `release` branch, which moves on every release; never add an overlay. Unlike `llm-agents`, it must keep `inputs.nixpkgs.follows = "nixpkgs"`: the addon links against the system fcitx5. Upstream has no binary cache, so every update compiles Rust + C++ locally; `packages.x86_64-linux.wowtype` re-exports it so the weekly workflow builds it before auto-merging. Settings live in the HM-forced `~/.config/fcitx5/conf/wowtype.conf` (`modules/nixos/input-method.nix`): booleans are the strings `True`/`False`, and the settings GUI replaces the symlink via `os.replace`, so `force = true` must stay.
- Binary caches are in `modules/nix.nix`; `flake.nix.nixConfig` is only bootstrap. Do not re-add `cache.garnix.io`. The two lists cannot be single-sourced — nix reads `nixConfig` as literals, so `import ./caches.nix` fails with `error: flake configuration setting 'extra-substituters' is a thunk` (verified). The CN mirror is intentionally in `nixConfig` (bootstrap paths: Live ISO `nix run --accept-flake-config`, `nix run .#nixos-anywhere`, `.envrc`) plus `hosts/mihomo-gateway` `nix.settings` (steady state + nixos-anywhere forwarding) — do not promote it to `modules/nix.nix`, the daily machines keep upstream caches.
- `home.stateVersion` and per-host `system.stateVersion` are migration markers; never bump them as part of routine updates. A deliberate bump targets the latest *released* version (currently NixOS/HM `26.05`, nix-darwin `7`), never unstable's in-flight release: weekly updates auto-merge, so a gate for an unreleased version would flip stateful defaults unreviewed. Before bumping, diff every host's toplevel drv against the previous commit and migrate whatever state the changed defaults touch. The 2026-11-16 bump changed no NixOS output; on Darwin it only dropped HM's `man-db` (macOS `/usr/bin/man` already finds the HM profile's man pages).

## Homebrew / Darwin

- Homebrew itself is declarative via `nix-homebrew` with `autoMigrate = true`, `mutableTaps = false`; bare machines should not run Homebrew install scripts manually.
- Brew itself is the `brew-src` flake input (a Homebrew/brew release tag), wired into nix-homebrew with `follows`. homebrew-core tracks master and adopts new bottle DSL as soon as a brew release supports it, while nix-homebrew's own pin lags; a stale brew fails `Homebrew bundle` with `undefined method 'manifest_sha256' for an instance of BottleSpecification`. So `just update` (also run by the weekly workflow, which commits `flake.nix` with the lock) first moves the tag to the latest release. nix-homebrew reads the brew version from its own `flake.lock`, so `modules/darwin/homebrew.nix` sets `nix-homebrew.package` with the version from this repo's lock.
- `homebrew.onActivation.cleanup = "zap"` uninstalls undeclared brews/casks including their prefs — removing a cask from the list is destructive on next switch. Darwin casks/MAS live in `modules/desktop/apps.nix` and in the feature files that own an app; taps and brews stay in `modules/darwin/homebrew.nix`; host-only casks stay under `hosts/<host>/`.
- Brew 6 requires non-official taps to be trusted. Keep `goooler/repo` and `imbytecat/tap` as `{ name = ...; trusted = true; }` and list all nix-homebrew-managed taps.
- Do not use removed Homebrew quarantine knobs (`caskArgs.no_quarantine`) or add automatic `xattr` bypass scripts; Gatekeeper exceptions are manual.
- `brew shellenv` comes from nix-homebrew, whose `enable{Zsh,Bash,Fish}Integration` default to true. Do not also set nix-darwin's `homebrew.enable*Integration` (it adds a second `brew shellenv` to every shell start) or hand-write `brew shellenv` snippets.
- MacBook Air intentionally uses raw `pmset`, not `power.sleep.*`, to preserve lid sleep behavior.

## Home Manager / Shell

- Prefer HM `programs.<name>` modules over `home.packages` when a module exists. Use current APIs: `programs.git.settings.*`, `programs.delta.*`, `programs.ssh.settings."*"`, and `programs.ssh.enableDefaultConfig = false`.
- `programs.gh` owns `~/.config/gh/config.yml`, so `gh alias set`/`gh config set` will fail against the read-only symlink — declare them in `programs.gh.settings` instead. Auth is `GH_TOKEN` from SOPS: GitHub's API cannot authenticate with an SSH key (`--git-protocol ssh` only affects git transport), and the keyring token was the last thing forcing an interactive `gh auth login` on a fresh machine.
- Do not set HM `programs.*.enableZshIntegration = true`; HM inherits shell integration by default. Only set `false` when deliberately disabling it.
- Static PATH entries go in `home.sessionPath`, not `path+=` in `initContent`.
- `shell/zsh.nix` opens `.zshrc` with `[[ -o interactive ]] || return` (`initContent` at `lib.mkOrder 0`); everything below it is interactive-only by design. Codex's shell snapshot sources `$ZDOTDIR/.zshrc` from a non-interactive zsh and sources the snapshot before every agent command, then `exec`s a fresh `zsh -c` (Codex 0.170 `maybe_wrap_shell_lc_with_snapshot`), so only exported variables reach the command; without the guard the snapshot grows from ~200 to ~7000 lines of plugin functions (measured). The guard also keeps zoxide's `cd` (`--cmd cd` jumps to a frecent directory when the target is missing) away from any tool that sources `.zshrc` directly. `defaultKeymap = "emacs"` because `EDITOR=nvim` makes zsh pick the vi keymap; the `sudo = "sudo "` alias expands the word right after `sudo` (not after `sudo -n`); `INTERACTIVE_COMMENTS` + `NO_NOMATCH` make pasted bash run as in bash.
- Platform branches should be Nix-time (`lib.optional`, `lib.optionalAttrs`, `pkgs.stdenv.hostPlatform.isDarwin`/`pkgs.stdenv.hostPlatform.isLinux`), not runtime `uname` checks. System-level modules should not need them at all — put platform-specific parts under the class key (`aspects.nixos.*` vs `aspects.darwin.*`).
- Host-only HM policy lives in the host module through `home-manager.users.${username}` — for example the awesome-pc Plasma power policy (powerdevil/kscreenlocker) in `hosts/awesome-pc/default.nix`. Do not gate shared HM modules on `osConfig.networking.hostName`.
- `mise` uses the Home Manager `programs.mise` module; shell integration follows HM defaults. Keep `all_compile = false` for precompiled runtimes on NixOS, and `trusted_config_paths = [ "/" ]` intentionally trusts every mise config without prompting. Projects pin their own toolchains (runtime versions, package managers, JDKs, Android CLI, release tools) in their mise config, which CI and Windows share; HM installs only what is needed outside any project plus editor/agent tooling, and `globalConfig.tools` stays empty (one-offs use `mise x`). Only interactive zsh runs `mise activate`, so `languages.nix` adds the shims dir to `home.sessionPath`: non-interactive shells, SSH commands and the T3 service (its PATH is built from `home.sessionPath`) resolve project pins per cwd, and outside a pinning project a shim falls back to the HM binary.
- Agent secrets use one SOPS recipient derived from the existing personal Ed25519 SSH key. `just secrets` edits the encrypted file. The first switch/deploy provisions a root-only age identity; the SSH login private key stays on the caller. A single recipient grants decryption of the entire file, and `modules/agents/secrets.nix` renders `agents.env`, `daily.env` and Tea configuration for `imbytecat` on each daily host. On Linux the sops service reloads T3 after decryption. On Darwin the launch agent references the ciphertext revision because Home Manager activates before sops-nix. See README for initial install and rollback.

## Mihomo Gateway

- Read `.agents/skills/mihomo/SKILL.md` before changing `modules/gateway/*`.
- Gateway business config comes only from `modules/gateway` + `hosts/mihomo-gateway`; the generic closure (base + server aspects, the `qemu-guest` and `systemd-boot` adapters, disko) is composed in `modules/hosts.nix`. Keep it isolated from daily-user features.
- Constants are plain attrs in `modules/gateway/_constants.nix` (the `_` keeps it out of the flake-parts auto-import), imported directly by `mihomo.nix` and `tproxy.nix`; do not turn them into NixOS options unless there is a real need.
- Use `tproxy-port`, not `listeners`. Do not set `routing-mark` in Mihomo config; nftables only intercepts PREROUTING and Mihomo outbound must not be routed back into itself.
- `rp_filter` must be disabled per-interface via networkd (`lo`, LAN interface patterns); sysctl `all/default` alone is insufficient.
- Keep `AF_NETLINK` in Mihomo `RestrictAddressFamilies`; without it UDP DIRECT silently fails while TCP may look fine.
- IPv6 forwarding is intentionally blocked by sysctl plus an `ip6` nftables forward chain that `reject`s (fast client fallback instead of a silent 1–3s stall). Do not re-enable casually.
- `firewall.enable = false` is intentional; nftables rules are owned by `modules/gateway/tproxy.nix`.
- `/etc/mihomo/env` (`CONFIG_URL` + `SECRET`) is written **by hand on the box, on purpose**. Do not add a nix/agenix/sops-nix/`op inject`+scp path for it — this was proposed and explicitly rejected. Everything else is declarative; this one file is not.
- Subscription flow: systemd `EnvironmentFile=` → sanitize every listener/API key out of the subscription → `mihomo -t` in an **isolated temp dir** (never the state dir: root would leave geo/cache.db root-owned and break `geo-auto-update`) → swap config → restart → `wait_healthy` → roll back to `.bak` on failure. Two non-obvious requirements: `systemctl restart` must keep `|| true` (otherwise `set -e` makes the rollback unreachable), and the health check must poll for ~10s rather than sleep once — with `RestartSec=5s` a single early `is-active` can catch a crash-looping unit mid-`activating` and call it success.
- DNS is explicitly excluded from the TPROXY rule (`th dport != 53`) so it is handled only by the `mihomo-dns` dstnat redirect. Without the exclusion it still works — mangle runs before dstnat and the NAT rewrite wins — but that is an implementation detail of TPROXY/NAT ordering, not a contract.
- `Restart = "always"` + `startLimitIntervalSec = 0` are deliberate: the gateway is a single point of failure, and systemd's default 5-starts-per-10s limit would park a crash-looping Mihomo in `failed` forever. Missing transparent sockets make nftables TPROXY skip its current rule (`NFT_BREAK`), so `tproxy.nix` follows it with a same-scope TCP/UDP non-DNS `drop`; private-address bypass and DNS redirection stay separate. **Do not add fail-open** (tearing down the tables via `ExecStopPost`): unproxied traffic through the GFW is worse than a loud outage. The isolated regression command lives in `.agents/skills/mihomo/SKILL.md`.
- `external-controller = "0.0.0.0:9090"` is intentional and must not be narrowed to loopback: this is a single-armed gateway with no WAN interface, so the wildcard is the LAN address, the API requires `SECRET`, and the zashboard UI is used from the desktop over the LAN. Audits keep flagging this; it is a considered decision.
- No socket-buffer sysctl tuning (`net.core.rmem_max` etc.): the running kernel already provides a 4 MiB ceiling and the subscription's outbounds are ss/vless, so quic-go never runs locally and never asks for its 7 MiB. Revisit only after switching to hysteria2/tuic nodes, and only with a real warning in the journal as evidence.
- No `flock` in the subscription script: systemd already serialises jobs for a single unit, so the timer, the path unit and a manual `systemctl start` cannot overlap.
- Threat model is asymmetric and deliberate: **only the gateway is hardened** (it faces the GFW — encrypted-only DNS, no plaintext upstream, sanitized external input, sandboxed units). Daily hosts optimize for convenience; passwordless sudo, no lock-screen password, `LSQuarantine = false`, broad `mise` trust and Homebrew auto-upgrade on Darwin are accepted trade-offs, not oversights. Do not "harden" them.
- The gateway is deliberately **not on the tailnet**: no foreign control-plane daemon on the hardened single point of failure, and gateway-local outbound is unproxied by design, so Tailscale through the GFW would be flaky anyway. Reach it over the LAN.

## Conventions

- Commit messages and in-file comments are zh-CN Conventional Commits: `feat(scope): 描述`, `fix(scope): 描述`, etc. README and `.agents/skills/` are zh-CN; this file is English on purpose (it is agent-facing).
- Comments are rare. Add only WHY/gotcha/cross-file coupling notes an agent would likely miss; do not label obvious packages or options.
- Telemetry: disable it only for vendors that turn it against the user; the call rests on vendor stance, not a proven mechanism (evidence: `docs/research/agent-telemetry-2026-11-23.md`). Claude Code: Anthropic is treated as hostile (account bans, a client-side detection experiment), so every opt-out stays on even though all API traffic goes to the gateway. `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is a documented enumeration, not a catch-all for future channels — newer ones got their own switches (`skipWebFetchPreflight`, marketplace auto-install) — so the single-purpose switches are set redundantly, and new opt-outs that appear in the env-vars/data-usage docs get added. Grok Build uploaded whole repositories plus git history; if a Grok CLI is ever installed, pin `[telemetry] trace_upload = false` in `~/.grok/config.toml`. Ordinary usage analytics are fine: existing one-line opt-outs may stay, but never add policy files, activation scripts or wrappers for them. Update checks on Nix-managed binaries are a separate, functional reason to switch something off.
- If docs conflict with executable config (`flake.nix`, `justfile`, module imports), trust the executable source and update docs.
