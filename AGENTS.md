# AGENTS.md

## Repo Shape

- Nix flake for `awesome-macbook-air` (`aarch64-darwin`), `awesome-pc` (`x86_64-linux`), `homelab-server` (`x86_64-linux`, root-only Docker VM), `mihomo-gateway` (`x86_64-linux`, root-only gateway), and `ovh-ks-5` (`x86_64-linux`, root-only Docker server). Uses Lix.
- Flake attr, host directory, and `networking.hostName` must match exactly; `just _guard` calls `_valid` first, then compares `hostname -s` with the host argument.
- Dendritic layout on flake-parts: `flake.nix` only declares inputs and auto-imports every `modules/**/*.nix` as a flake-parts module; paths containing `/_` are plain data or helpers imported by path. One feature per file: a feature contributes plain NixOS / nix-darwin / Home Manager modules to role aspects `aspects.<class>.<role>` (option in `modules/flake/aspects.nix`). A feature that spans platforms stays in one file and keeps its platform differences in the class key, not in conditionals. Aspects are deliberately not `flake.modules`: Lix warns `unknown flake output 'modules'`.
- Roles: `base` (every host of a class), `daily` (daily-driver hosts; NixOS, Darwin and Home Manager), `desktop` (GUI hosts), `server` (root-only NixOS), plus NixOS adapters `gateway`, `qemu-guest`, `systemd-boot`, `grub-raid`. `modules/hosts.nix` composes every host — Darwin and daily NixOS = base + daily + roles, servers = base + server + roles — then appends `hosts/<host>/` (hardware, disks, single-host overrides) and `networking.hostName`. Adding a host is one line there plus `hosts/<host>/`; its `checks.x86_64-linux.eval-<host>` is generated.
- Inner modules get `inputs` and `sshKeys` through `specialArgs`, plus `username` on daily hosts only; servers deliberately get no `username` because nothing in their closure needs one. Home Manager gets `inputs` and `username` through `extraSpecialArgs`. There is no `system` arg: use `pkgs.stdenv.hostPlatform.system` in config values. Flake-level code (hosts, packages, checks) uses the top-level flake-parts `inputs`/`config`.
- Servers' baseline intentionally avoids Home Manager, catppuccin, fish, 1Password, docker, unfree and desktop features — all of those contribute only to `daily`/`desktop`. Server hosts add only their business need: `mihomo-gateway` composes the `gateway` aspect, while `homelab-server` and `ovh-ks-5` enable Docker and Tailscale in their host modules.

## Commands

- Local activation: `just switch <host>`; hostname mismatch is refused. NixOS-only: `just boot <host>`, `just rollback`.
- Build without activating: `just build <host>`. Compare current generation: `just diff <host>` (auto-builds first). Hunt cache misses: `just dry <host>`.
- Checks: `just fmt`, `just eval`, `just check`. `just eval` only covers current-platform hosts, but eval-only cross-checks work from Linux too: `nix eval .#darwinConfigurations.<host>.system.drvPath` (building/activating Darwin still needs a Mac). Run evals sequentially — parallel `nix eval` can die on a busy eval-cache SQLite.
- Flake evals only see git-tracked files. `git add` new `.nix` files before any `nix eval`/`just build`, or you get "No such file or directory" against the store copy of the repo.
- `nix fmt` formats the whole repo via treefmt (config in `treefmt.nix`, currently nixfmt only); `just fmt` is just an alias. Do not go back to hand-assembling a file list.
- `nix flake check` (= `just check`) evaluates every host **and** runs `checks.formatting` (treefmt) + `checks.lint` (statix + deadnix). Both are expected to be clean — a warning is a regression, not background noise. `just lint` runs the linters alone.
- NixOS install/update: 首装优先从另一台机器运行 `just install <host> <remote>`（nixos-anywhere, `--build-on remote`）；Live 本机备用路径直接运行本仓 `packages.x86_64-linux.disko-install`，显式传 `--flake`、`--disk` 和 `--write-efi-boot-entries`；之后用 `just deploy <host> <remote>` / `just deploy-boot <host> <remote>`。
- `disko-install` **忽略** flake 里的 `device`，强制 CLI `--disk <name> <path>`（见上游 install-cli.nix）。`awesome-pc` 默认 by-id 在 `hosts/awesome-pc/disko.nix`；Live 对不上时只替换 CLI 设备路径。本地安装使用已提交的 hardware config。`just install` only asks nixos-anywhere to generate hardware config when `hosts/<host>/hardware-configuration.nix` is git-tracked (untracked files never reach the target build); generation overwrites that file in the caller worktree before the target build.
- `just install` deliberately passes **no** substituters/keys/experimental-features: nixos-anywhere defaults to `machineSubstituters=y`, which evals the target's `nix.settings.{substituters,trusted-public-keys}` and appends them to the installer's `~/.config/nix/nix.conf`, and it already puts `--extra-experimental-features 'nix-command flakes'` on every nix invocation (`src/nixos-anywhere.sh`). Do not re-add a hand-written cache list there — it silently drifts from `nix.settings`. Only `--no-substitute-on-destination` / `--no-use-machine-substituters` turn that off; `--option` does not.
- `.vscode/settings.json` is committed and static: nixd `options` mounts nixos + nix-darwin + home-manager option sets side by side (representative hosts `awesome-pc` / `awesome-macbook-air`; option *declarations* come from imported modules, so same-class hosts share them). No generation step.
- `nix develop` provides repo tools (`just`, `nixd`, `nixfmt`, `statix`, `deadnix`, `nvd`, `nix-tree`, treefmt wrapper) without relying on the host HM profile. Its `nixfmt` is `treefmt.config.programs.nixfmt.package` on purpose: `.vscode/settings.json` makes nixd format with bare `nixfmt`, so format-on-save must resolve to the exact binary `nix fmt` and `checks.formatting` use. Without it, Mac would fall back to the HM copy from `nixpkgs-unstable`, which can drift from the repo's `nixpkgs`.
- `homelab-server` is a Proxmox VE QEMU VM with systemd-boot, DHCP, VirtIO initrd support, QEMU guest agent, root-only access, and Docker. Its disko target defaults to `/dev/sda`; change the host-local default before a destructive install if PVE presents another device.
- `ovh-ks-5` is OVH bare metal: `/dev/nvme{0,1}n1`, RAID1 ESP at `/boot/efi` (vfat, 512 MiB, md metadata 1.0), RAID1 `/boot` (ext4, 2 GiB, metadata 1.2), and RAID1 ext4 root (metadata 1.2). It uses GRUB hybrid/removable boot, DHCP, root-only access, and Docker with its built-in Compose plugin. Its tracked `hardware-configuration.nix` is the first-install generation target; commit the target scan after `just install`.
- `ovh-ks-5` backups live in `hosts/ovh-ks-5/backup.nix`: one `services.restic.backups.stacks` job snapshots `/opt/stacks` (every stack keeps its bind mounts inside its own directory, dockge-style) plus `/var/lib/docker/volumes`, so a single snapshot is a movable machine. `backupPrepareCommand` probes every running container for `pg_dumpall` and writes `/opt/stacks/.dumps/<container>.sql.zst` into the tree — logical dumps, because a tar of a live PG data dir is only crash-consistent. A failed dump does **not** abort the snapshot: it drops a `FAILED-<name>` marker and `backupCleanupCommand` fails the unit afterwards, so a partial snapshot still lands but never looks green.
- `/etc/restic` contains exactly the hand-written `repository` and `password` files; SFTP needs no environment file. The service never initializes a repository automatically: `restic-stacks init` is an explicit first-creation step, so a wrong repository URL fails closed instead of silently creating an empty history. Keep `/etc/restic/{repository,password}` and `/root/.ssh/id_ed25519` in 1Password; this deliberate exception mirrors `/etc/mihomo/env`, so no agenix/sops-nix.
- The restic target is a HostBrr Storagebox over SFTP, and **this repo is public**, so no hostname/username/port goes into git. `/etc/restic/repository` holds the full `sftp://user@host:port//abs/path` URL; no `/root/.ssh/config` alias or `known_hosts` priming. `backup.nix` uses `StrictHostKeyChecking=accept-new`; verified with both SSH files deleted that backup succeeds, pins the key, and restores a canary. The oneshot unit has no 90-second start cap. Its daily `--read-data-subset=2%` check is random corruption sampling, not deterministic 50-day coverage.

## Where Things Go

- Cross-platform features live in top-level files or topic dirs under `modules/`: `nix.nix` (Lix, caches, registry, weekly GC with `--delete-older-than 30d` — systemd `dates` on NixOS, launchd `interval` on Darwin —, `trusted-users` on daily hosts, store optimise on servers), `users.nix` (the human account and sudo; Darwin puts it in base because nix-darwin's homebrew and user defaults need `system.primaryUser`), `ssh.nix` (sshd everywhere, root keys and hardening on servers, the HM SSH client), `home.nix` (HM integration for daily hosts plus HM base packages), `catppuccin.nix`, `fonts.nix`, `1password.nix`, `tailscale.nix`, `shell/`, `dev/`, `agents/`, `desktop/`.
- Platform-only plumbing lives in `modules/nixos/` (`base`, `daily`, `desktop`, `input-method`, `server`, and the `qemu-guest`/`systemd-boot`/`grub-raid` adapters) and `modules/darwin/` (`homebrew`, `defaults`); `modules/gateway/` is the NixOS-only gateway role.
- `aspects.nixos.base` holds only what every NixOS role needs: Nix settings, disko, locale/timezone, sshd, zram, the landing CLI baseline (curl, git, lsof, pciutils, usbutils, smartmontools) and Ghostty terminfo. Role-shaped facts go to `daily`/`server`, adapters stay separate, machine facts go to `hosts/<host>/`. Server echo tools (btop, neovim, ouch) stay in `nixos/server.nix`: hoisting them into base would double-install them on daily hosts where HM owns the configured version. Every NixOS host composes exactly one boot adapter; base is bootloader-agnostic.
- Do not create a Docker wrapper or aspect while its shared implementation is one native line. Daily NixOS enables Docker in `nixos/daily.nix` and grants the `docker` group in `users.nix` (a user privilege); root-only Docker servers enable it in their host modules. The default nixpkgs Docker package already carries the Compose plugin, so do not add `docker-compose`. `services.tailscale.enable` follows the same pattern: `tailscale.nix` for daily hosts (with the Darwin `tailscale-app` cask), host-local for servers that want it, never on `mihomo-gateway`.
- `modules/desktop/apps.nix` is the single GUI app list for both desktops: `both` maps each Homebrew cask to the nixpkgs attr of the same app, and platform-only casks/MAS/packages sit in the same file. Apps with configuration, services or special install needs get their own feature file instead (`1password.nix`, `tailscale.nix`, `shell/ghostty.nix`, `desktop/herdr.nix`). XWayland Qt5 apps that need fcitx env (`wechat-fcitx`, `wpsoffice-fcitx`) are wrapped in the overlay. Single-host casks/packages stay in `hosts/<host>/default.nix` (for example `thaw`); GPU drivers are hardware and stay there too.
- `modules/nixos/desktop.nix` owns Plasma 6 (Wayland-only + SDDM), NetworkManager, printing/Avahi, AppImage binfmt, Bluetooth and Logitech peripherals (`programs.solaar` installs Solaar and enables `hardware.logitech.wireless`; piper/ratbagd are intentionally not installed), plus the user's Plasma/Konsole HM config through `home-manager.users.${username}`. `modules/nixos/input-method.nix` owns fcitx5 + WowType, the keyd CapsLock mapping and the matching HM fcitx5 files. Linux-only HM config is written from these NixOS modules so it can never reach Darwin.
- `modules/shell/ghostty.nix` holds everything Ghostty: the Darwin cask, the HM settings (Linux installs the package through HM because the HM module's systemd/D-Bus integration needs one; Darwin uses `package = null`), and the terminfo in NixOS base.
- `modules/dev/languages.nix`: shared development runtimes/tooling (`bun`, `go`, `nodejs`, `python3`, `uv`, `fvm`, `mise`, `android-tools`, LSPs, linters). An LSP/formatter/linter earns its place only when omp's `lsp` tool, a VS Code extension, or agent shell sessions actually resolve it from PATH; VS Code extensions that bundle their own server do not count (evidence: `docs/research/dev-language-tools-2026-11-15.md`). Neovim (`modules/dev/neovim.nix`) is plain `programs.neovim` on purpose: LazyVim was removed because it was barely used and its extras expected tools that were never installed. `android-tools` is enough for `adb`/`fastboot`; in 2026 nixos-unstable no longer needs `programs.adb`, `adbusers`, or `android-udev-rules` because systemd 258 handles uaccess.
- `modules/agents/` 分成两条轴：`_bundles/` 声明跨 agent 的 **behavior bundle**，`codex.nix`、`codex-plugins.nix`、`omp.nix`、`dsh.nix`、`skills.nix` 只负责映射到 Codex plugin、OMP extension/rule、DSH patch 与共享 skill 目录。`_bundles/default.nix` 是 plain-attr registry，不创建 repo option；Ponytail/Caveman 的 pin-specific packaging、OMP 文件和 skill 取舍只在各自 bundle 改。`_ai-catalog.nix` 是 AI gateway endpoint、provider identity、model IDs/metadata 的唯一来源（plain attrs，由 `agents/default.nix` 通过 `_module.args.aiCatalog` 注入 HM daily，fish 的 op-env 也用它）。Models 位于 `providers.<family>.<nick>`（统一 schema；anthropic/openai/furtherverse family 名是全仓字面共享词汇）；映射文件通过扁平 `models.<nick>` view（含 `provider`）、`ref "<nick>"`（→ `provider/id`）或 `providers.<family>` 投影消费。模型/endpoint 只在 catalog 改，不在映射文件分散修改。
- Agent 映射的落法：`codex.nix` 只管 Codex package/model/provider；`codex-plugins.nix` 聚合 bundle plugin、Codex 0.146 cache 兼容层与激活时的 hook 信任；`omp.nix` 生成 `~/.omp/agent/{models,config}.yml` 并合并 bundle 的 extension/files；catalog→gateway provider 投影单一化在 `_gateway-providers.nix`：OMP 整体写入 models.yml，DSH 只取 api/baseUrl/apiKey；`skills.nix` 把 bundle 与 skill-only 输入逐项 link 到 `~/.agents/skills`，父目录保持可写。
- DeepSeek Harness：`agents/dsh.nix` 安装 `llm-agents` 的 `dsh`（跨平台，命中 `cache.numtide.com`；nixpkgs 的 `deepseek-harness` 仅 Linux 且版本更旧），并只写 home 级 `~/.dsh/cordis.patch.yml`（叠在每个 profile 之后），用 `llm-pi-ai` 的 `furtherverse` 路由（`openai-completions`，api/baseUrl 取自 `_gateway-providers.nix`）挂 catalog 的 `deepseek` 并设为 `agent-default-model`。不用原生 `llm-deepseek`：它默认把整段 `dsh_session_log`（每请求至多 8 MiB）作为额外字段发给 `baseURL`。网关的 `reasoning_effort` 接受 `off`，所以 `off` 显式映射为 `"off"`，不用 `thinkingFormat`。patch 按 id 整行替换 config，UI 在 profile patch 里改的同名行会被它覆盖。
- DSH 隐私与搜索：同一 patch 把 `session-telemetry-otel` 行 `disabled: true`（等同 `DSH_TELEMETRY_DISABLED` 的启动 patch；默认 `FEEDBACK_ONLY` 会在点赞/点踩/`/feedback` 后上传整段 session log 到 `dsh-otel-collector.deepseeksvc.com`）。`desktop` profile 才挂的 product analytics 不处理。内置 `web_search`/`web_fetch` 的 `web` 行改为 `deepseek-search-api`/`deepseek-fetch-api`：只认官方 `DEEPSEEK_API_KEY`（op-env 注入），与聊天路由无关，不耗模型 token；网关会丢弃 `web_search_20250305` server tool（实测），所以不能指向网关。本地 `http` fetch 的 SSRF 校验拒绝 mihomo fake-ip `198.18.0.0/15`，在网关后面全部失败，所以 fetch 也交给 DeepSeek。该行 config 整行替换，两个 provider 都必须写明。
- DSH 权限：同一 patch 的 `permission` 行把新会话默认预设设为 `danger-full-access`（完全文件访问 + `never` 审批，对齐 Codex 的 `never` + `danger-full-access`）。DSH 的 `never` 是自动拒绝而非自动批准，只因完全访问下没有需要升权的操作才等于免授权。该行 config 整行替换，必须照抄上游的 `read-only`/`workspace-write`/`danger-full-access` 三个预设；`/permission` 与 `dsh headless --permission-mode` 仍可逐会话切换。不用上游的 `DSH_PERMISSION_MODE` 环境变量：它只在带 HM 会话变量的 shell 里生效，与 telemetry 选 patch 的理由相同。
- ponytail（`inputs.ponytail`，`flake = false`）是 behavior bundle，不等于某个 host 的 plugin：`omp.nix` 把上游仓库根目录列进 `extensions`，loader 认 `package.json` 的 `pi.extensions`，`before_agent_start` 每轮注入 ruleset 并注册 `/ponytail` 档位与 `/ponytail-*` 命令；`codex-plugins.nix` 经 HM marketplace/cache 加载上游正式 plugin。`materializeCodexPlugins` 在 link 后把 store symlink 落成真实可清理目录（Codex 0.146 只把真实目录算 installed）。Codex 把 hook 的信任同时钉在声明 hash 与整个插件目录的内容 hash 上，插件或 Codex 一更新，手钉的 hash 就失效，hook 静默报 `Failed`（曾因此长期没生效）；Codex 没有持久的“信任全部”开关（`--dangerously-bypass-hook-trust` 只管单次调用，`app-server` 也不认）。所以不钉 hash，由 `trustCodexHooks` 激活步骤经 `codex app-server` 的 `hooks/list` + `config/batchWrite`（与 TUI 审批同一写法）信任 Codex 在 `$HOME` 下列出的全部 hook；Codex 本来就是 `never` 审批 + 完全访问，这一步不扩大权限。项目自带的 `.codex/` hook 不在其列，仍按项目审批。Ponytail skills 由两边 plugin 自带，不再铺共享副本。
- caveman（`inputs.caveman`，ponytail 的另一半）也是 behavior bundle，但上游没有 Pi adapter：`agents/_bundles/caveman.nix` 给 OMP 提供 always-apply rule 与 `/caveman` command，给 Codex 生成封装上游 `.codex/hooks.json` 的最小 lifecycle plugin；上游命令从 git 根目录找 `codex-sessionstart.js`，只在 caveman 自己的仓库里成立，bundle 把它改指 store 中的脚本，上游改写法时求值报错。共享 skills 同样由该 bundle 导出。`cavecrew` 与 `caveman-stats` 不铺（前者依赖 Claude subagent，后者依赖 Claude session hook），`caveman-shrink` 保持 opt-in。
- 手机派活（试用中）：`agents/paseo.nix` 与 `agents/t3code.nix` 不手写服务。T3 用 HM `programs.t3code`：装包、把 omp 的 Local ACP 合并进 `settings.json`（命令名必须是 `omp`），`server` 起 launchd agent / systemd user service；`--lan` 监听全部地址，配对 token 是唯一门槛，NixOS 只在 `tailscale0` 放行 3773 并开 linger。模块的服务不经 login shell，所以给它补 PATH、op-env 的 dotenv（`environmentFile`）和遥测开关（`T3CODE_TELEMETRY_ENABLED=false`/`T3CODE_OTEL_SDK_DISABLED=true`，同时放 session 变量给 CLI），macOS 的 `ProcessType` 改回 `Interactive`。Paseo 只有上游 NixOS 模块（`inputs.paseo` 只取 `nix/module.nix`）：系统服务以用户身份运行，relay 关、`tailscale0` 放行 6767，`EnvironmentFile` 指向 op-env 的 dotenv；macOS 没有现成服务，需要时手动起 daemon。`~/.paseo/config.json` 由 CLI 与手机 App 改写，HM 激活时只合并 omp provider（默认模型与 `omp.nix` 的 `modelRoles.default` 一致：Paseo 否则挑模型列表第一个，网关不提供会一直 503）和 relay 关闭；密码用 `paseo daemon set-password` 设。
- mattpocock/skills（`inputs.mattpocock-skills`）是 skill-only distribution，不是 behavior bundle：22 个流程 skill（grilling → to-spec → to-tickets → implement/tdd → code-review）由 `agents/skills.nix` link 到 `~/.agents/skills`。只取 `skills/{engineering,productivity}`（= 上游 `.claude-plugin/plugin.json` 清单），不铺 `deprecated`/`in-progress`/`misc`/`personal`。13 个带 `disable-model-invocation` 的 skill 只能显式调用；实测 Codex/OMP 都只暴露同 9 个 model-invocable skill。用前每仓跑一次 `/skill:setup-matt-pocock-skills` 生成 `docs/agents/{issue-tracker,domain,triage-labels}.md`；升级 `nix flake update mattpocock-skills`。

## Nix / Package Gotchas

- Darwin pkgs are imported in the `darwin` helper of `modules/hosts.nix` from `inputs.nixpkgs-unstable` with `allowUnfree` and overlays; do not add `nixpkgs.config` in Darwin modules.
- NixOS `allowUnfree` and overlays are in `modules/nixos/daily.nix`, so servers (base + server aspects) have neither in their closure; do not move them into base. `nix-ld` is part of `nixos/daily.nix` (headless remote development needs it too), not a desktop or host concern.
- Repo-local packages 由 `overlays/default.nix` 统一 `callPackage` 后暴露为 `pkgs.<name>`；模块只消费 `pkgs`，`flake.packages` 复用同一 attr。不要从模块写 `callPackage ../../pkgs/...`，否则 package seam 泄漏仓库布局。
- Channels are disabled. `modules/nix.nix` pins registry and the shared `nix.nixPath` to flake `inputs.nixpkgs`; do not add `<nixpkgs>`/channel-based paths. Keep this working cross-platform option until nix-darwin migrates its `NIX_PATH` handling too; the NixOS rename warning is an accepted exception, not a reason to add a platform-specific mapping.
- `llm-agents` packages are consumed directly via `inputs.llm-agents.packages.${pkgs.stdenv.hostPlatform.system}.*` in `modules/agents/` and, for the herdr desktop app, in `modules/desktop/herdr.nix`; never add an overlay. Darwin deliberately skips the Homebrew `herdr-app` cask: the release build enables telemetry and self-updates, the Nix build has neither. `herdr-core` is listed beside `herdr-app` because the phone app and other machines reach `hc` over SSH, outside the app wrapper's PATH. `omp` and Codex report status to herdr natively via OSC 7501, so no herdr integration or hook is installed. `packages.x86_64-linux.herdr-app` re-exports the unmodified input derivation for CI/manual builds. `llm-agents` intentionally does not follow this repo's nixpkgs; changing that will miss `cache.numtide.com`.
- WowType (fcitx5 pinyin addon) is consumed directly as `inputs.wowtype.packages.${pkgs.stdenv.hostPlatform.system}.default` from the upstream `release` branch, which moves on every release; never add an overlay. Unlike `llm-agents`, it must keep `inputs.nixpkgs.follows = "nixpkgs"`: the addon links against the system fcitx5. Upstream has no binary cache, so every update compiles Rust + C++ locally; `packages.x86_64-linux.wowtype` re-exports it so the weekly workflow builds it before auto-merging. Settings live in the HM-forced `~/.config/fcitx5/conf/wowtype.conf` (`modules/nixos/input-method.nix`): booleans are the strings `True`/`False`, and the settings GUI replaces the symlink via `os.replace`, so `force = true` must stay.
- Binary caches are in `modules/nix.nix`; `flake.nix.nixConfig` is only bootstrap. Do not re-add `cache.garnix.io`. The two lists cannot be single-sourced — nix reads `nixConfig` as literals, so `import ./caches.nix` fails with `error: flake configuration setting 'extra-substituters' is a thunk` (verified). The CN mirror is intentionally in `nixConfig` (bootstrap paths: Live ISO `nix run --accept-flake-config`, `nix run .#nixos-anywhere`, `.envrc`) plus `hosts/mihomo-gateway` `nix.settings` (steady state + nixos-anywhere forwarding) — do not promote it to `modules/nix.nix`, the daily machines keep upstream caches.
- `home.stateVersion` and per-host `system.stateVersion` are migration markers; never bump them as part of routine updates. A deliberate bump targets the latest *released* version (currently NixOS/HM `26.05`, nix-darwin `7`), never unstable's in-flight release: weekly updates auto-merge, so a gate for an unreleased version would flip stateful defaults unreviewed. Before bumping, diff every host's toplevel drv against the previous commit and migrate whatever state the changed defaults touch. The 2026-11-16 bump changed no NixOS output; on Darwin it only dropped HM's `man-db` (macOS `/usr/bin/man` already finds the HM profile's man pages).

## Homebrew / Darwin

- Homebrew itself is declarative via `nix-homebrew` with `autoMigrate = true`, `mutableTaps = false`; bare machines should not run Homebrew install scripts manually.
- `homebrew.onActivation.cleanup = "zap"` uninstalls undeclared brews/casks including their prefs — removing a cask from the list is destructive on next switch. Darwin casks/MAS live in `modules/desktop/apps.nix` and in the feature files that own an app; taps and brews stay in `modules/darwin/homebrew.nix`; host-only casks stay under `hosts/<host>/`.
- Brew 6 requires non-official taps to be trusted. Keep `goooler/repo` and `imbytecat/tap` as `{ name = ...; trusted = true; }` and list all nix-homebrew-managed taps.
- Do not use removed Homebrew quarantine knobs (`caskArgs.no_quarantine`) or add automatic `xattr` bypass scripts; Gatekeeper exceptions are manual.
- `homebrew.enableFishIntegration = true` is required for nix-darwin Homebrew integration; do not replace it with shell `brew shellenv` snippets.
- MacBook Air intentionally uses raw `pmset`, not `power.sleep.*`, to preserve lid sleep behavior.

## Home Manager / Shell

- Prefer HM `programs.<name>` modules over `home.packages` when a module exists. Use current APIs: `programs.git.settings.*`, `programs.delta.*`, `programs.ssh.settings."*"`, and `programs.ssh.enableDefaultConfig = false`. One checked exception stays a raw package on purpose: `devenv` — the module's only added value is a fish `hook` that auto-enters/exits project shells on `cd`, which fights the direnv setup this repo already uses.
- `programs.gh` owns `~/.config/gh/config.yml`, so `gh alias set`/`gh config set` will fail against the read-only symlink — declare them in `programs.gh.settings` instead. Auth is `GH_TOKEN` from op-env, not the keyring: GitHub's API cannot authenticate with an SSH key (`--git-protocol ssh` only affects git transport), and the keyring token was the last thing forcing an interactive `gh auth login` on a fresh machine.
- Do not set HM `programs.*.enableFishIntegration = true`; HM inherits shell integration by default. Only set `false` when deliberately disabling it.
- Static PATH entries go in `home.sessionPath`, not `fish_add_path` in `interactiveShellInit`.
- Fish functions belong in `programs.fish.functions`; do not put function definitions back into `interactiveShellInit`.
- Platform branches should be Nix-time (`lib.optional`, `lib.optionalAttrs`, `pkgs.stdenv.hostPlatform.isDarwin`/`pkgs.stdenv.hostPlatform.isLinux`), not runtime `uname` checks. System-level modules should not need them at all — put platform-specific parts under the class key (`aspects.nixos.*` vs `aspects.darwin.*`).
- Host-only HM policy lives in the host module through `home-manager.users.${username}` — for example the awesome-pc Plasma power policy (powerdevil/kscreenlocker) in `hosts/awesome-pc/default.nix`. Do not gate shared HM modules on `osConfig.networking.hostName`.
- `mise` uses the Home Manager `programs.mise` module; shell integration follows HM defaults. Keep `all_compile = false` for precompiled runtimes on NixOS, and `trusted_config_paths = [ "/" ]` intentionally trusts every mise config without prompting.
- 1Password env vars are cached in `~/.cache/op-env/env.fish`; `op-env-refresh` is manual and uses `OP_SERVICE_ACCOUNT_TOKEN` from `~/.config/fish/local.fish`. It also writes `~/.cache/op-env/env` (`KEY="value"`) for launchd/systemd `EnvironmentFile`s, which cannot read fish syntax.

## Mihomo Gateway

- Read `.agents/skills/mihomo/SKILL.md` before changing `modules/gateway/*`.
- Gateway business config comes only from `modules/gateway` + `hosts/mihomo-gateway`; the generic closure (base + server aspects, the `qemu-guest` and `systemd-boot` adapters, disko) is composed in `modules/hosts.nix`. Keep it isolated from daily-user features.
- Constants are plain attrs in `modules/gateway/_constants.nix` (the `_` keeps it out of the flake-parts auto-import), imported directly by `mihomo.nix` and `tproxy.nix`; do not turn them into NixOS options unless there is a real need.
- Use `tproxy-port`, not `listeners`. Do not set `routing-mark` in Mihomo config; nftables only intercepts PREROUTING and Mihomo outbound must not be routed back into itself.
- `rp_filter` must be disabled per-interface via networkd (`lo`, LAN interface patterns); sysctl `all/default` alone is insufficient.
- Keep `AF_NETLINK` in Mihomo `RestrictAddressFamilies`; without it UDP DIRECT silently fails while TCP may look fine.
- IPv6 forwarding is intentionally blocked by sysctl plus an `ip6` nftables forward chain that `reject`s (fast client fallback instead of a silent 1–3s stall). Do not re-enable casually.
- `firewall.enable = false` is intentional; nftables rules are owned by `modules/gateway/tproxy.nix`.
- `/etc/mihomo/env` (`CONFIG_URL` + `SECRET`) is written **by hand on the box, on purpose**. Do not add a nix/agenix/sops-nix/`op inject`+scp path for it — this was proposed and explicitly rejected. Everything else is declarative; this one file is not.
- Subscription flow: systemd `EnvironmentFile=` → sanitize every listener/API key out of the subscription → `mihomo -t` in an **isolated temp dir** (never the state dir: root would leave geo/cache.db root-owned and break `geo-auto-update`) → swap config → restart → `wait_healthy` → roll back to `.bak` on failure. Two non-obvious requirements: `systemctl restart` must keep `|| true` (otherwise `set -e` makes the rollback unreachable), and the health check must poll for ~10s rather than sleep once — with `RestartSec=5s` a single early `is-active` can catch a crash-looping unit mid-`activating` and call it success.
- DNS is explicitly excluded from the TPROXY rule (`th dport != 53`) so it is handled only by the `mihomo-dns` dstnat redirect. Without the exclusion it still works — mangle runs before dstnat and the NAT rewrite wins — but that is an implementation detail of TPROXY/NAT ordering, not a contract.
- `Restart = "always"` + `startLimitIntervalSec = 0` are deliberate: the gateway is a single point of failure, and systemd's default 5-starts-per-10s limit would park a crash-looping Mihomo in `failed` forever. Missing transparent sockets make nftables TPROXY skip its current rule (`NFT_BREAK`), so `tproxy.nix` follows it with a same-scope TCP/UDP non-DNS `drop`; private-address bypass and DNS redirection stay separate. **Do not add fail-open** (tearing down the tables via `ExecStopPost`): unproxied traffic through the GFW is worse than a loud outage. The isolated regression command lives in `.agents/skills/mihomo/SKILL.md`.
- `external-controller = "0.0.0.0:9090"` is intentional and must not be narrowed to loopback: this is a single-armed gateway with no WAN interface, so the wildcard is the LAN address, the API requires `SECRET`, and the zashboard UI is used from the desktop over the LAN. Audits keep flagging this; it is a considered decision.
- No socket-buffer sysctl tuning (`net.core.rmem_max` etc.): the running kernel already provides a 4 MiB ceiling and the subscription's outbounds are ss/vless, so quic-go never runs locally and never asks for its 7 MiB. Revisit only after switching to hysteria2/tuic nodes, and only with a real warning in the journal as evidence.
- No `flock` in the subscription script: systemd already serialises jobs for a single unit, so the timer, the path unit and a manual `systemctl start` cannot overlap.
- Threat model is asymmetric and deliberate: **only the gateway is hardened** (it faces the GFW — encrypted-only DNS, no plaintext upstream, sanitized external input, sandboxed units). Daily hosts optimize for convenience; passwordless sudo, no lock-screen password, `LSQuarantine = false`, broad `mise` trust and Homebrew auto-upgrade on Darwin are accepted trade-offs, not oversights. Do not "harden" them.
- The gateway is deliberately **not on the tailnet**: no foreign control-plane daemon on the hardened single point of failure, and gateway-local outbound is unproxied by design, so Tailscale through the GFW would be flaky anyway. Reach it over the LAN.
